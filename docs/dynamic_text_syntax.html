Syntax guide

Dynamic text syntax

Combine ordinary text with values and expressions. The same syntax is used for text evaluated directly and for prepared text patterns.

Braces evaluate. {name} inserts a value.

Single quotes keep text literal. '{name}' produces {name}.

Example inputsSwitch between template text and its JSON encoding.

Examples assume name = Ada and ready = true, unless stated otherwise.

01Values and expressions

Write ordinary text directly. Surround a variable or a function call with {…}. Use dots to access fields: {person.name}, {window_size.w} or {object.array.0}. Array indexes start at zero. Global settings use paths such as {global.gui_run}.

Template textHello {name}
ResultHello Ada

Functions use {function:argument:argument}. The function comes first; colons separate its arguments. Nest another expression inside an argument when you need its result.

Template text{+:1:{*:2:3}}
Result7

A bare argument is text: name means the word “name”; {name} means its value. Text returned by a variable is inserted without evaluating it again. If label contains {name}, then {label} inserts those literal braces and that name.

02Single quotes make literal strings

Inside paired single quotes, braces and colons are literal text. Expressions inside that span do not expand. Outside a collection, the surrounding quote marks are removed.

Template textHello '{name}'
ResultHello {name}
Template text{if:{ready}:Hello {name}:'Please wait'}
ResultHello Ada
Template text{if:{ready}:'Hello {name}':'Please wait'}
ResultHello {name}

Use '' for an empty string. When a quoted literal is decoded, \n, \t, \r, \b, \f and \uXXXX decode as JSON escapes. Use \\ for a literal backslash and \' for an apostrophe. For example, 'path\\name' produces path\name; 'path\name' contains a newline. An unknown escape such as \q produces q.

Use single quotes for template literals. The double quotes around a JSON string belong to JSON; they do not disable expression expansion.

03Separators and escapes

A colon separates arguments at the current expression level. Colons inside a single-quoted argument, a nested expression or an array do not split the surrounding call. Spaces in ordinary text remain part of that text.

Use single-quoted spans for literal punctuation, and place expressions outside those spans:

Template textMeaning
'{name}'Literal {name}, without expanding the expression.
':'A literal colon within an argument.
'It\'s ready.'An apostrophe inside a quoted literal.
'\\'A single literal backslash.
Template text'{name}': {name}
Result{name}: Ada
Template text{if:{ready}:Name':' {name}:'Waiting'}
ResultName: Ada

Unquoted backslashes remain in the output; they do not make braces literal. A colon in ordinary text outside an expression is already literal. JSON adds its own escaping layer; see Writing JSON.

04Arrays and maps

Arrays use square brackets and comma-separated items. Quote a string item when it contains a comma. Quotes within a collection are retained so the item boundaries survive evaluation.

Template text['a,b','c']
Result['a,b','c']
Template text{array_length:['a,b','c']}
Result2

The same literal-string rule applies inside arrays: ['{name}','other'] keeps {name} literal. Collection helpers may return serialized items with their quotes still attached:

Template text{at:0:['a,b','c']}
Result, including quotes'a,b'

Map data also uses braces. Quote the whole map when passing a literal map to a function, so its braces and colons are treated as data:

Template text{at:key:'{key:value,other:ignored}'}
Resultvalue

Single quotes protect text from expression expansion. A function can still interpret the resulting text as a number, a condition or a collection.

05Conditions and loops

Use {if:condition:then:else} to choose text. The else argument is optional; without it, a false condition produces an empty result. Only the selected branch is evaluated.

Template text{if:false:{missing}:'OK'}
ResultOK

Write boolean values as true and false. Quoting false does not turn it into a true condition: {if:'false':yes:no} produces no.

{&&:a:b} means “and”; {||:a:b} means “or”; {not:a} negates a condition. “And” and “or” evaluate arguments from left to right and stop as soon as the result is decided.

Produce an array with for

Use {for:item:array:expression}. Within the expression, {item} is the current element. Each result becomes an element of the output array.

Template text{for:n:[1,2,3]:{*:2:{n}}}
Result[2,4,6]

06Writing a template in JSON

JSON is decoded first. The resulting string is then evaluated as a template. JSON's outer double quotes never make the template literal.

{
  "type": "text",
  "text": "Hello {name}"
}

This displays Hello Ada. Changing the text value to "Hello '{name}'" displays Hello {name}.

Double each backslash required by the template when writing it inside JSON:

1 · JSON field"text": "Say '{name}', then {name}. 'It\\'s ready.' C:\\data"
2 · Decoded templateSay '{name}', then {name}. 'It\'s ready.' C:\data
3 · ResultSay {name}, then Ada. It's ready. C:\data

The “JSON value” switch above shows the JSON encoding of each example input. It changes how the example is written, not what the template produces.

07Action strings

An ordinary action is written as name:argument:argument. The application supplies the action names. Arguments use the same expressions as text and are resolved before the action is called.

"action": "select:{name}"

With a select action available, this passes Ada as its argument. The quoting and escaping rules are the same as for text:

"action": "notify:'Saved: {name}'"
"action": "notify:'Saved: '{name}"

The first passes the literal argument Saved: {name}. The second passes Saved: Ada.

A whole action enclosed in braces is an expression that produces a complete command. For example, {if:{ready}:start:stop} chooses the start or stop action. A generated command is split into its name and arguments without expanding its resolved text a second time.

08Names and valid syntax

  • A required variable or function must exist. An unknown required name is an error.
  • Use a leading dot for an optional lookup: {.missing} produces an empty result when the name is absent.
  • Use {#value} to format a value for rich-text display, including escaping angle brackets.
  • Use paired braces and paired single quotes. An empty expression {}, a mismatched brace or an unterminated quoted literal is invalid. A trailing backslash in ordinary template text is preserved.
  • Keep intended expressions outside literal quotes, and use prefix calls such as {+:2:3} for calculations.
Examples show template results. The receiving layout property or action may interpret that text as a value of its own type.
